# 問いの型

構造を決める問いは、抽象的な二択ではなく**具体例**で聞く。開発者が具体例に答えたら、その答えを事例として
残す。下の各問いの「→」は、答えが用語集のどこに入るか（書式は `glossary` スキルの `CONTEXT-FORMAT.md`）。

## 種別（kind）

1 語について、次の順に聞く。

1. **同一性**: 「この X とあの X が同じものかは、何で決まりますか？」 → `_種別_`。自分で同一性を持たず値で比べるなら
   `value`。起きたことなら `event`。複数の語を結びつけること自体が実体なら `relator`
2. **固定性**: 「ある X が、X でなくなって、それでも同じものとして存在し続けることはありますか？
   （例: 田中商事が顧客でなくなっても田中商事のまま）」
   - なくならない → `kind`（上位の語が無い）か `subkind`（上位の語がある）
   - なくなりうる → 何によってなくなるかを聞く。他との関係で決まるなら `role`、自分の状態で決まるなら `phase`
3. **上位の語**: role / phase / subkind なら「X は何の一種ですか？」 → `_上位_`。定義も「〔上位の語〕のうち、
   〔違い〕であるもの」の形にそろえる

よくある誤り: role を kind として扱う（「顧客」という種類のものがいるのではなく、当事者が注文を出したときに
顧客と呼ばれる）。これを誤ると、同じ人が顧客と取引先の両方になる場面で実装が破綻する。

## 兄弟の関係（排他・重なり・網羅）

同じ上位の語を持つ語の組ごとに聞く。`lint` の `UNSTATED` がそのまま問いのリストになる。

- **排他か重なりうるか**: 「1 つの当事者が、個人であり同時に法人であることはありますか？」 → 排他なら
  上位の語の `_分割_` / `_排他な下位_`、重なりうるなら `_重なりうる_`。重なりうるなら、その具体例を
  `expect: possible` の事例にする
- **網羅**: 「当事者のうち、個人でも法人でもないものはありますか？」 → 無いなら `_分割_` / `_網羅する下位_`、
  あるなら `_網羅_: no`（その例を possible の事例に）

## 関係と多重度

関係 1 つにつき、両方向を聞く。0 の場合を必ず聞く（書き漏れやすいのは「0 個」）。

- 「1 つの注文を出した当事者は、何人ありえますか？ 0 人は？ 2 人は？」 → 関係の表の `inverse`
- 「1 つの当事者が出す注文は何件ありえますか？ 0 件の当事者は？」 → 関係の表の `mult`
- 「0 件の当事者は顧客ですか？」のように、関係が語の定義に関わるなら公理にする（例の `AX1`: `Customer = places.Order`）

## 公理と帰結

- 開発者が「〜は必ず〜」「〜は決して〜ない」と言ったら、それが**定め**なのか、他から**導かれるはず**のことかを
  聞く: 「それは独立に決めることですか、それとも〜から当然そうなることですか？」 → 定めなら公理、導かれる
  なら帰結
- 帰結を足したら `verify` で導けるか確かめる。導けなければ、足りない公理を 1 つに絞って提案する

## 境界を突く事例

公理が出揃ったら、自分で境界の事例を作って聞く。

- 空の場合: 「注文を 1 件も持たない当事者」「発送の無い確定した注文」
- 重なりの場合: 「顧客であり仕入先でもある当事者」
- 状態の端: 「確定した後に取り消した注文に発送はあるか」
- 多重度の端: 「同じ注文に 2 回目の発送」

答えを `expect: possible` / `impossible` で残す。`impossible` なのに `verify` が実例を出したら（TOO-LOOSE）、
禁じる公理が足りない。

## 言っていないことの扱い

開発者が「そこは考えていない」「どちらでもいい」と答えたら、黙って埋めない。

- 「どちらでもいい」→ 本当にどちらでもよい（制約を課さない）なら、その旨を明示する（重なりなら `_重なりうる_`、
  網羅なら `_網羅_: no`）
- 「まだ決めていない」→ `_状態_: open` か `_網羅_: open` にして未決事項に書く
- 「扱わない」→ 対象外に書く
