# CONTEXT.md の書式

用語集（`CONTEXT.md`）は、1 つのコンテキストに固有の語について、**定義**（何であるか）と**構造**（語どうしが
どう関係するか）を持つ。構造は、語ごとの**構造の行**と、語にまたがる命題の節（関係・公理・帰結・事例・
未決事項・対象外）からなる。どれも省略でき、定義だけの用語集もこの書式に従っている。

置き場（ルートの `CONTEXT.md` か、`CONTEXT-MAP.md` が指す各コンテキストか）は `project-layout` スキルが決める。

## 構造

```md
---
verification: markdown   # 省略可。構造を検証する方式: markdown | alloy
alloy-scope: 4           # 省略可。alloy で探す各集合の要素数の上限
---

# {コンテキスト名}

{このコンテキストが何で、なぜ存在するかを 1〜2 文で。}

## 用語

**注文（Order）**:
顧客が商品の購入を申し込んだ記録。
_使わない_: 購入、トランザクション
_種別_: kind
_分割_: 下書きの注文、確定した注文、取り消した注文

**確定した注文（PlacedOrder）**:
注文のうち、確定して発送を待つか発送されたもの。
_種別_: phase
_上位_: 注文

**顧客（Customer）**:
当事者のうち、注文を 1 件以上出したもの。
_使わない_: 購入者、クライアント
_種別_: role
_上位_: 当事者
_重なりうる_: 個人、法人
_コード_: Customer

## 関係

| id | name | from | to | mult | inverse | status | meaning |
|----|------|------|----|------|---------|--------|---------|
| R1 | places | 当事者 | 注文 | set | one | confirmed | [[当事者]] が [[注文]] を出す |

## 公理

### AX1: 顧客とは注文を出した当事者
- statement: [[当事者]] が [[顧客]] であることと、[[注文]] を 1 件以上出していることは同値
- alloy: `Customer = places.Order`

## 帰結
## 事例
## 未決事項
## 対象外
```

frontmatter と、「用語」より後の節は、構造を書くときだけ置く。

## 語の定義

- **態度を決める。** 同じ概念に複数の言葉があるなら、いちばん良いものを 1 つ選び、残りは `_使わない_` に並べる。
- **定義は短く。** 最大 1〜2 文。何を**するか**ではなく何**であるか**を書く。上位の語があるなら
  「〔上位の語〕のうち、〔違い〕であるもの」の形にし、`_上位_` の行と一致させる。
- **このプロジェクトの文脈に固有の用語だけ。** 一般的なプログラミング概念（タイムアウト、エラー型、ユーティリティの
  パターン）は、プロジェクトが多用していても載せない。足す前に「この文脈に固有の概念か、一般的な概念か」を
  問い、前者だけを載せる。
- **自然な塊ができたら小見出しで分ける。** 「用語」の下に `###` の小見出しを置いてよい。全部が 1 つの
  まとまりなら平らな一覧でよい。
- **実装の詳細を入れない。** `CONTEXT.md` は用語集であって、仕様でも、走り書きでも、実装上の決定の置き場でもない。
  例外は構造の行 `_コード_` だけで、語が実装のどの識別子に当たるかを書く（実装とのずれを見つけるため）。

見出し（`**語（English）**:`）の括弧の中は別名で、英語の識別子にできる名前を入れる。語を廃止したら見出しを
消し、残した語の `_使わない_` に移す。

## 構造の行

定義と `_使わない_` の後に、1 行に 1 項目で書く。ラベルは用語集の言語に合わせる（英語の用語集では右の列）。
値の語は `、` か `,` で区切る。

| ラベル | English | 値 | 意味 |
|---|---|---|---|
| `_種別_` | `_Kind_` | 下の「種別」の 1 つ | 語の種類。構造を持つ語には必ず書く |
| `_上位_` | `_Is-a_` | 語 | この語の実例は、すべて上位の語の実例でもある。複数なら、そのすべてに属する |
| `_分割_` | `_Partition_` | 下位の語 | 並べた下位の語は互いに排他で、合わせるとこの語全体になる。組が複数なら行を繰り返す |
| `_排他な下位_` | `_Disjoint-children_` | 下位の語 | 並べた下位の語は互いに排他（全体にはならなくてよい） |
| `_網羅する下位_` | `_Covering_` | 下位の語 | 並べた下位の語を合わせるとこの語全体になる（重なってよい） |
| `_重なりうる下位_` | `_Overlapping-children_` | 下位の語 | 並べた下位の語は互いに重なりうる |
| `_網羅_` | `_Complete_` | `no` / `open` | 下位の語で網羅されない（`no`）、未定（`open`）。網羅するなら `_分割_` か `_網羅する下位_` を使う |
| `_排他_` | `_Disjoint_` | 語 | この語と排他な語（兄弟でなくてよい） |
| `_重なりうる_` | `_Overlaps_` | 語 | この語と重なりうる語 |
| `_状態_` | `_Status_` | `confirmed` / `assumed` / `open` | 構造の確かさ。省略すると `confirmed`。`assumed`（暫定で採る）と `open`（未定。制約として使わない）は「未決事項」から参照する |
| `_コード_` | `_Code_` | 識別子 | 実装上の識別子 |
| `_ID_` | `_Id_` | 識別子 | 検証のモデルで使う名前。省略すると見出しの括弧の中の英語名 |

### 種別

| 種別 | 何か | 例 |
|---|---|---|
| `kind` | 実例の同一性を与える最上位の種類。実例は存在する間ずっとその種類 | 当事者、注文 |
| `subkind` | kind の下位で、実例は存在する間ずっとそれのまま | 個人、法人 |
| `role` | 他との関係によって一時的に当てはまる | 顧客（注文を出したから顧客） |
| `phase` | 自分の状態によって一時的に当てはまる | 確定した注文 |
| `relator` | 複数の語を結びつけること自体が実体になったもの | 契約、雇用 |
| `event` | 起きたこと。時点を持つ | 発送 |
| `value` | 同一性を持たず、値で比べるもの | 金額、住所 |

`subkind` / `role` / `phase` は `_上位_` を必ず持つ。

### 書いていないことの意味

- 同じ上位の語を持つ 2 つの語について、排他とも重なりうるとも書いていなければ、それは**未定**であって、
  どちらかに決まっているのではない。
- 下位の語を持つ語について、網羅されるともされないとも書いていなければ、それも未定。
- `_上位_` を持たない、種別のある語どうしは、互いに排他として扱う（同じものが 2 つの最上位の種類に属することはない）。

## 語にまたがる節

### 関係

表 1 つ。`mult` は「from の各実例が、to の実例をいくつ持つか」、`inverse` は「to の各実例が、from の実例から
いくつ指されるか」。値は `one`（ちょうど 1）/ `lone`（0 か 1）/ `some`（1 以上）/ `set`（制約なし）。
`name` は検証のモデルで使う名前で、語の名前と重ねない。`meaning` の中の語は `[[語]]` で参照する。

### 公理・帰結・事例

`###` の見出し 1 つにつき 1 件。見出しは `ID: 短い題`。

- **公理**: 正しいと**定める**命題
- **帰結**: 公理と構造から**導かれるはず**の命題。導かれなければ、公理が足りないか見込みが誤り
- **事例**: 具体的な状況が起こりうるか（`expect: possible`）起こりえないか（`expect: impossible`）

各項目は箇条書きの欄を持つ。

| 欄 | 必須 | 値 |
|---|---|---|
| `statement` | ○ | 自然言語の命題。語は `[[語]]` で参照する |
| `expect` | 事例では ○ | `possible` / `impossible` |
| `status` | | `confirmed`（既定）/ `assumed` / `open` |
| `alloy` | | 命題を Alloy の式で書いたもの。1 行ならバッククォートで、複数行なら直後に ```` ```alloy ```` のコードブロックで |
| `scope` | | この項目だけ Alloy で探す大きさを変えるとき |

### 未決事項・対象外

箇条書き。未決事項は `- Q1: 問い（related: 語、語）` の形で書く。対象外には、意図して扱わないことを書く
（例: 時間に沿った状態の移り変わりは扱わない）。

## CONTEXT-MAP.md

コンテキストが複数あるときだけ置く。各コンテキストの所在と、コンテキストどうしの関係を書く。

```md
# コンテキストマップ

## コンテキスト

- [注文](./src/ordering/CONTEXT.md): 顧客の注文を受け付けて追跡する
- [請求](./src/billing/CONTEXT.md): 請求書を発行し支払いを処理する
- [出荷](./src/fulfillment/CONTEXT.md): 倉庫でのピッキングと発送を管理する

## 関係

- **注文 → 出荷**: 注文が `OrderPlaced` イベントを出し、出荷がそれを受けてピッキングを始める
- **出荷 → 請求**: 出荷が `ShipmentDispatched` イベントを出し、請求がそれを受けて請求書を作る
- **注文 ↔ 請求**: `CustomerId` と `Money` の型を共有する
```

構造の行と命題の節が参照できるのは、同じ `CONTEXT.md` の語だけ。
