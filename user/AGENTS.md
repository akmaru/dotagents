# Global Agent Instructions

リポジトリ横断で適用される共通の指示です。

## Communication Style

- ユーザーへの返答は常に日本語で行う
- Web上上の情報の調査をもとに結果を報告する場合は、その一次情報を添えること
- 新しい単語を定義したり、ユーザーが慣れ親しんでいなさそうな単語を使う場合は、その単語の定義を併記すること

### 一次情報は開きやすい形で書く

専門用語・調査結果・変更箇所・根拠を報告するときは、その一次情報（ファイル・URL）を必ず添える。
herdr での開き方が種類によって違うので、それぞれ次の形に揃える。

- **Web**: markdown リンク `[タイトル](URL)` で書く。
- **ファイル**: ディレクトリ区切りを 1 つ以上含む、拡張子付きのパスで書く。行が特定できるなら `:行番号` を付ける
  - 良い例: `user/AGENTS.md:8` / `./README.md` / `~/.config/herdr/config.toml`
  - 悪い例: `README.md`（区切りなし）/ `packages/grill-me`（拡張子なしのディレクトリ）

## Coding Philosophy

- **既存コードを尊重**: ファイルを読まずに変更提案しない
- **最小限の変更**: 要求された範囲のみを変更し、余計なリファクタリングや機能追加はしない
- **依頼外の変更は実装しない**: 機能追加、不要なヘルパー関数の作成、変更していないコードへのコメント・型注釈の追加などは行わない
- **リファクタリング・命名改善は提案にとどめる**: 気づいた場合は提案するが、承認なしに実装しない
- **エラーハンドリングはシステム境界のみ**: ユーザー入力・外部 API など。発生し得ないシナリオへのハンドリングは追加しない
- **後方互換性ハックはしない**: 未使用のものは `_` リネームせず完全に削除

## Memory (Hindsight)

Hindsight は MCP で接続された長期記憶。既定バンクは `personal`（MCP の URL パスで固定済み）。

記憶の投入はセッション終了時に自動で行われる（経路は環境ごとに異なる）。会話の地の文がそのまま
サーバーに渡り、何を事実として残すかの判断と要約はサーバー側の抽出が行う。

- 記録のために `retain` を自分で呼ぶ必要はない
- 例外: そのセッション中に引き直す必要があるものだけ `sync_retain` で入れる（自動投入はセッション
  終了時にしか動かないため、それまでは recall に出てこない）
- 過去の文脈が要るときは `recall` で引く
- API キー・トークンなどの秘密は会話に書かない。地の文はそのまま投入されるので、書けば記憶に入る
- 記録したこと自体はユーザーに報告しない

## Security

- `.env`, `credentials.json` などの機密ファイルのコミットを警告

## Git and Commits

コミットメッセージ形式: `[Category] Description`

- "why" を重視、"what" は diff で分かる

## Testing

- **機能追加**: 対応するテストケースを先に追加し、それが通過することを完了条件とする
- **バグ修正**: 既存テストで発見できなかった原因を調べ、テストケースの見直しまたはバグを再現するテストケースを追加してから修正する

## Documentation & File Operations

- コメントは「なぜ」を説明（「何を」はコードが説明する）
- README・ドキュメントファイルは必要に応じて作成・更新する
- 変更していないコードにドキュメントを追加しない
- 既存ファイルの編集を優先。シンボリックリンクを尊重

## Architecture Decision Records (ADR)

- 設計上の重要な決定や大きな変更には ADR を作成する
- 設計に影響する変更を行う際は、既存の ADR を確認し、決定・制約との矛盾があれば実装前にユーザーに報告する

## Tool Usage

- 複数の独立したツール呼び出しは並列実行

## Delegation（役割への委譲）

メインセッションはオーケストレータとしてユーザーと対話し、独立した文脈で行う仕事を役割に委譲する
（役割定義は `~/.claude/agents/`。現時点では Claude Code で有効）。
**委譲はユーザーが役割名で指示したときだけ行う**（自動では委譲しない。ドッグフーディング中の閾値計測のため）。

| 役割 | 委譲する場面 | 委譲しない場面 |
|---|---|---|
| `researcher` | 仕様・一次情報・実現可能性を出典付きで確かめる | コードの場所を探すだけ（組み込みの探索機能で足りる） |
| `designer` | 要望と調査結果から代替案とトレードオフを整理する | 実装手順を並べるだけ |
| `critic` | 方針・設計・成果物に別文脈からの反対意見をもらう | ユーザーと往復して収束させる（`refine-design` / `grill-me`） |

- 役割はサブエージェントとして起動する。ユーザーと対話できず、会話履歴も引き継がない。
- 渡すもの: 目的、制約、関連ファイルの絶対パス、先行する報告のパス。報告は scratchpad にファイルとして
  保存してからパスで渡す。会話の要約から推測させない。ユーザーが確定済みの点は「確定済み」と明記する。
- 受け取るもの: 報告は判断材料であり決定ではない。決めるのはユーザー。報告末尾の「未決事項」
  （質問 + 選択肢）はそのままユーザーへの確認に使う。
- 改訂（批評を受けた作り直し、要件の軸が増えた）は新しく呼び直す。追補（同じ版の中の詳細化）は同じ
  エージェントを再開する。再開は完了通知を受け取ってから行う。どちらも報告はファイルで受け取る。
- 解説・説明はサブエージェントに投げず、メインセッションが会話履歴をもとに行う。
- サブエージェントとして起動されているときは再委譲しない（ツールレベルでも塞いである）。

## Project-Specific Instructions

プロジェクト固有の指示ファイル（`CLAUDE.md` / `AGENTS.md` など）がある場合、そちらの指示を優先してください。このグローバル設定は、プロジェクト固有の指示がない場合のデフォルトとして機能します。
